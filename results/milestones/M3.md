## What was formalized (GraphLab kernel library, no Mathlib deps in Decide)

`lean/GraphLab/Decide.lean` — kernel-computable decision procedures on
explicit `Nat -> Nat -> Bool` matrices: `colorable`, `chiExactly`,
`existsClique`/`cliqueNumber`, `independenceNumber`,
`isValidBranchModel`/`hasKMinorScan`/`hadwigerNumber` (branch-set codes,
digit 0 = deleted vertex — the same deletion-tolerant semantics that fixed
the Rust engine in M2; both sides re-derived independently in Lean).

`lean/GraphLab/MathlibBridge.lean` — `ofBoolMatrix` builds a Mathlib
`SimpleGraph (Fin n)` from the same explicit matrix through Mathlib's own
`SimpleGraph.mk'` (symmetry + irreflexivity supplied as decidable Bool
proofs), with theorem `adj_iff` tying bridge adjacency to the engine-view
Bool value.

`lean/GraphLab/Facts.lean` — LEAN_CHECKED facts (kernel-re-evaluated,
values agree with Rust engine AND Python oracle):

| theorem | statement | kernel method |
|---|---|---|
| `K4_irr`/`K4_sym` | explicit K4 matrix is a simple graph law pair | `decide` (16 cases) |
| `K4.Adj ↔ K4A …` | bridge/engine agreement, all pairs | `adj_iff` |
| `K4_not_colorable_3` | K4 is not 3-colorable | full 81-coloring scan **inside the kernel** |
| `K4_colorable_4` | explicit coloring certificate (code 228) | kernel verifies certificate |
| `K4_chi` | chiExactly 4 4 K4A = true | both directions above |
| `K4_has_K4_minor` | explicit branch-set certificate code 586 | certificate + lemma `hasKMinor_of_model` |
| `K4_hadwiger` | h(K4) = 4 | certificate feeds structural `hadwigerGo` |
| `P4_colorable_2`, `P4_not_colorable_1` | chi(P4)=2 | certificate + 1-code scan |
| `C5_not_colorable_2` | odd cycle not bipartite (full 32-scan) | kernel scan |
| `C5_colorable_3` | explicit 3-coloring certificate | kernel verifies |
| `hadwigerNumber_le` | h(G) ≤ |V| structural | no computation at all (pure proof) |

These are genuine finite graph facts with real content (K4 needs 4 colors
— equivalently the canary predicate is falsified at K4; C5 needs 3 — the
odd-cycle theorem at a concrete instance), not tautologies: each is the
kernel's own exhaustive verdict or a verified certificate for the exact
quantified negation of a universal claim at a concrete instance.

## Semantic audit (per docs/PROOF_TRUST_MODEL.md)

- English "finite simple undirected graph" == Mathlib `SimpleGraph (Fin n)`
  == engine `Graph`: irreflexive symmetric adjacency. The Lean facts take
  the matrix literally: `K4A i j` is TRUE only on the listed ordered pairs
  of DISTINCT vertices; irreflexivity/symmetry examples above are the
  machine check.
- `colorable` in Lean is the exact "exists proper k-coloring" predicate on
  the concrete vertex set `Fin n` (digits base k over `List.range n`),
  matching the engine's DFS coloring semantics: both say "a map
  V -> {0..k-1} with adjacent vertices distinct".
- `hasKMinor` in Lean is the exact "t disjoint connected pairwise-adjacent
  branch sets covering a subset" minor predicate, matching the corrected
  engine semantics (deletion allowed).
- `scripts/formalize.py` generates witness->Lean files from the same
  encodings; the canary/hadwiger predicate bodies have explicit English +
  audit-header blocks (no auto-translation of unknown predicates: they are
  rejected with a typed error).

## Known limitations / trust additions (honest)

1. Kernel scans are feasible only for small instances: the heaviest here is
   C5-not-2-colorable (32 colorings) and K4-not-3-colorable (81). n<=7-ish
   for coloring scans, n<=5-ish for full branch-set scans (4^5 codes ×
   model-check). This is the price of kernel-checking instead of
   `native_decide` (which we forbid by policy). Larger campaigns stay on
   the Rust/Python engines; only certificate-shaped results cross into
   Lean (as with K4_minor).
2. No Mathlib chromatic-number/minor API is *proved* to coincide with our
   kernels yet (`SimpleGraph.chromaticNumber`, `HasSubgraph`-style minor
   relations). The `adj_iff` bridge theorem ties the *graph object*, but a
   `GraphLab.colorable ↔ SimpleGraph.Colorable` dictionary theorem is the
   next formalization task; until then the kernel facts are self-contained
   exact statements about the explicit matrices, which is what the witness
   bridge requires (they re-evaluate the ENGINE's definition, not a
   Mathlib-abstract one).
3. `lake build` runs on this host only (CI lean job gated `if: false` —
   mathlib download in CI would exceed the bounded-workload rule; a lean
   CI job with cache is a post-M6 decision).
